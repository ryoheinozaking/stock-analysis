# TradingView 統合 設計

作成日: 2026-09-12

## 背景

TradingView の有料プランを契約しているが、現状は日足チャートを目視で見るだけで活用しきれていない。
Claude と TradingView を接続する MCP サーバーが話題になっており（X の紹介投稿が発端）、
これを機に「トレードにもっと活用する」方法を設計する。

当初は紹介記事に従って `tradesdontlie/tradingview-mcp` を導入する方向で進めたが、
検証の結果いくつか前提が覆ったため、設計をやり直した。本書はその検証結果と方針を記録する。

## 検証で確定した事実

調べ直すコストが高いため、根拠とともに残す。

### TradingView 利用規約は自動収集を明示的に禁止している

利用規約は「スクリプト、API、スクリーンスクレイピング、データマイニング、ロボット等による
自動的なデータ収集を、**その目的を問わず**厳格に禁止する」と定めている。
市場データは「表示のみ」の用途に限ってライセンスされ、表示以外の利用は禁止。
[How bans work](https://www.tradingview.com/support/solutions/43000591357-how-bans-work/) には
この制限に違反した場合アカウントを BAN すると明記されている。

MCP サーバーが行っているのは、まさにこの禁止対象に該当する。
CDP 経由でのデータ取得に加え、ログイン Cookie を使って内部 API
（`pricealerts.tradingview.com`、`pine-facade.tradingview.com`、`symbols_list`）を直接呼んでいる。

一方で、実際に MCP 利用で BAN された報告は確認できなかった。
スター 6,000 規模のツールが約半年運用されて大量 BAN 事件が起きていない状態。
ただしツール作者自身が「アカウント BAN について責任を負わない」と免責している。

**方針**: 利用者のアカウントに関する自己責任の判断として、フル活用する。
ただし失うものを最小化するため、Pine スクリプトとレイアウトの事前バックアップを A-0 に含める。

### Advanced Charts は個人利用では使えない

TradingView 公式の無料チャートライブラリ [Advanced Charts](https://www.tradingview.com/advanced-charts/) は、
当初「自前サーバーにホストして J-Quants データを流せば規約違反ゼロで使える」と判断したが、これは誤りだった。

ライセンス条件は「**法人**が**公開**のウェブプロジェクトやアプリで使う場合にのみ提供」であり、
「**個人利用・趣味・学習・テスト目的では提供しない**」と明記されている。
stock_analysis は個人の投資判断用ツールのため条件を満たさない。

**代替**: [Lightweight Charts](https://github.com/tradingview/lightweight-charts) は Apache 2.0 の
オープンソースで、個人利用・商用ともに制限がない。Streamlit 用ラッパーも存在し、
特に `streamlit-lightweight-charts-v5` はマルチペイン（価格＋MACD＋RSI の縦積み）に対応する。
系統 B はこちらで実現する。

### 日本株は約 20 分遅延、ただし本件では問題にならない

リアルタイムデータ購読なしでは東証銘柄は約 20 分遅延する（リアルタイムは月額約 3 ドルの別購読）。
現状は未契約と見られる。

ただし stock_analysis の戦略はバリュー株 250 日保有・成長株 60 日保有が前提であり、
リアルタイム性は元々必要ない。**逆に言えば、MCP でリアルタイム監視する価値も低い**。
MCP の価値は日足ベースの「チャート判断の壁打ち」と「候補の一括確認」に集中する。

売買タイミングの通知は、日次で足りるため stock_analysis 側で実装する方が筋が通る（将来課題）。

### MCP リポジトリの実態

| 項目 | 値 | 評価 |
|---|---|---|
| スター | 6,117 | 解説記事の数字（5,000/5,381）より多く、記事が古い |
| フォーク | 2,650 | スター比 43% は異常に高い。転載フォークが多数存在 |
| 未解決 Issue | 241 | 97 コミットの規模に対して多い |
| 最終 push | 2026-07-28 | 約 1.5 ヶ月停止。Issue は積み上がったまま |
| ライセンス | Other | 標準 OSS ライセンスではない |
| 初コミット | 2026-03-16 | リポジトリ公開は 2026-03-29 |

コードの静的検査結果は問題なし。

- 外部通信先は `*.tradingview.com` とローカル CDP のみ。第三者サーバーへの送信なし
- `eval` / `new Function` / `vm.runIn` はゼロ件
- `child_process` は git 操作・TradingView 起動・自己更新用の `npm ci` のみ
- 環境変数アクセスは CDP 設定と TradingView のパス解決のみ。認証情報の読み取りなし

注意点として `src/core/update.js` に自己更新機構（`git pull` + `npm ci`）がある。
将来のコードが自動で入る経路になるため、リポジトリが乗っ取られた場合の影響範囲が広い。

### 環境: TradingView は MSIX パッケージとして導入済み

Windows 版 TradingView は MSIX 形式（`TradingView.Desktop_n534cwy3pjxzj`）でインストールされている。
`C:\Program Files\WindowsApps\` 配下は権限制限があり、CDP のデバッグポート起動が
"Access is denied" で失敗する既知の問題がある。

リポジトリ側は `tv_launch` ツールで MSIX を自動検出し、失敗時は
`%LOCALAPPDATA%\tradingview-mcp\` へローカルコピー（約 330MB）してそこから起動するフォールバックを実装済み。
ただし環境によっては追加対応が必要との報告もあり、**動作保証はない**。これが A-0 で潰すべき最大の不確実性。

### MCP 設定の書き込み先

`~/.claude/.mcp.json` に書いても読み込まれなかった。
実際に効いているのは `~/.claude.json` のトップレベル `mcpServers` フィールド。
`claude mcp add -s user` で登録するのが正しい。

なお EDINET DB は `claude mcp list` に現れず、デスクトップアプリ独自のコネクタ管理で
登録されているため別系統である。

## スコープ分解

要望は 5 つ挙がったが、技術的に独立した 2 系統に分かれる。

### 系統 A: MCP 活用（規約リスクあり・Claude Code ワークフロー）

- **A-0**: 技術検証＋資産バックアップ
- **A-1**: 深層分析への統合
- **A-2**: 候補絞り込み（Top-N 一括巡回）
- **A-3**: エントリー／保有監視の壁打ち

A-0 は A-1 以降の前提。ここが動かなければ系統 A は成立しない。

### 系統 B: Streamlit チャート刷新（規約クリーン・stock_analysis のコード）

- **B-1**: Lightweight Charts で `components/chart.py`（333 行・Plotly）を刷新

系統 A とは依存関係がなく、独立して進められる。
インジケーターの計算ロジックは再利用し、描画層のみ差し替える。
なお Plotly は `4_portfolio.py` / `7_pipeline_report.py` / `8_backtest_value.py` でも使われているが、
そちらは対象外とする。

### 着手順

A-0 → A-1 → （B-1 / A-2 / A-3 は後日判断）

## A-0 設計: 技術検証＋資産バックアップ

### 目的

1. MSIX 環境で MCP が実際に動くか
2. 実チャートから何が取れるか（Supertrend、SQZMOM 等のカスタムインジケーターが読めるか）
3. 同梱 `tv` CLI の能力範囲
4. Pine・レイアウト・ウォッチリストの吸い出し

3 が **A-1 の設計を左右する**。MCP ツールは Claude Code 経由でしか呼べないが、
CLI なら Python から `subprocess` で呼べるため、既存の `scripts/deep_analysis_helper.py` と
同じパターンに乗せられる可能性がある。

### 手順

1. `claude mcp add -s user tradingview -- node C:/Users/ryohei/tradingview-mcp/src/server.js`
2. Claude Code 再起動
3. `tv_health_check` で接続確認
4. 失敗時は `tv_launch` で MSIX フォールバックの動作を確認
5. `chart_get_state` / `data_get_study_values` で 5016 の実データ取得
6. Pine 一覧取得 → `pine_get_source` で全スクリプト吸い出し
7. ウォッチリスト取得
8. `tv` CLI の能力確認（Python 連携の可否判定）

### 成果物

| 出力 | 保存先 | git |
|---|---|---|
| Pine ソース | `data/tradingview/pine/*.pine` | 管理する |
| チャート状態 JSON | `data/tradingview/state/` | 管理する |
| スクリーンショット | `data/tradingview/screenshots/` | 除外（`.gitignore` に追記） |
| 検証結果 | 本設計書の「A-0 実施結果」節に追記 | 管理する |

検証結果を会話内の報告だけで終わらせると、次のセッションで A-1 を設計する際に
何が取れて何が取れなかったかが失われる。本設計書に追記して残す。

### リスク

- `tv_launch` は TradingView を `taskkill` で強制終了してから起動し直す。開いている画面が一度閉じる
- MSIX フォールバックが走ると約 330MB のローカルコピーが作られる
- 以降 CDP ポート 9222 が開いた状態になる。ローカルの任意プロセスから TradingView を操作可能になる

### 分岐条件

- **動作した** → 取れたデータを見て A-1 を詳細設計
- **動作しない** → MSIX 回避を追うか、系統 A を見送り B-1 へ切り替えるかを相談

## A-1 方向性（A-0 の結果で確定）

深層分析レポートの **4.5 テクニカル状況** が統合先。
現状は `scripts/deep_analysis_helper.py` 由来の J-Quants 客観データ
（MA5/25/60/200、RSI、MACD、52 週レンジ、出来高、予想 PER）で埋まっている。

TradingView が追加できるのは汎用指標ではなく「利用者固有のチャート環境」である。

- カスタム Pine インジケーター（Supertrend、Squeeze Momentum 等）の状態
- 自分で引いた描画（トレンドライン等）
- 実際の画面のスクリーンショット

したがって 4.5 を **2 層構成**にする。

1. J-Quants 客観指標（全銘柄同一基準・バックテストで検証済み）
2. 自分のチャート環境（実際に判断に使っている道具）

両者が食い違ったときに指摘できることが、この統合の主な価値になる。

TradingView が起動していない場合はスキップし、深層分析自体は従来どおり完結させる（オプショナル扱い）。

実装形態は A-0 の結果次第で以下から選ぶ。

- **案 1**: `SKILL.md` の Step 1.5 と 4.5 を拡張。既存フローに自然に乗るが、SKILL.md が更に肥大（現在 605 行）
- **案 2**: `tv` CLI 経由のヘルパースクリプトを作り `deep_analysis_helper.py` と同じ形に揃える。A-2 でも再利用可能。CLI の能力が足りることが前提
- **案 3**: 専用スキルとして切り出す。責務は分離されるがスキル間連携が複雑になる

## 保留事項

- 売買タイミングの通知は stock_analysis 側で日次実装する方向（本設計のスコープ外）
- B-1 の詳細設計は A-0/A-1 完了後
- リアルタイムデータ購読（月額約 3 ドル）は現状不要と判断
