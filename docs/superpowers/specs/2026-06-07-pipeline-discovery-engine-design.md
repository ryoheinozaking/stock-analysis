# パイプライン発掘エンジン化 Phase 1（SEPA組み込み + シグナル再設計 + 二刀流動線）設計

**作成日**: 2026-06-07
**対象**: `services/pipeline_service.py` / `pages/7_pipeline_report.py`
**起点**: 同日の発掘パイプライン・メタ分析（[[飛躍分析スキル新設と発掘動線 セッション 2026-06-07]]）で「成長株モードのテクニカルスコアが SEPA Stage4 を BUY にする欠陥」を発見
**承認**: ユーザ承認済み（2026-06-07・対話で全判断を確定）

---

## 背景と目的

EDINET screen と自前パイプラインの突き合わせで、**成長株モードのテクニカルスコアが SEPA ステージ（長期トレンド方向）を一切見ておらず、下降トレンド（Stage4）中の RSI 戻りを「好テクニカル」と誤評価して BUY 上位に出す**欠陥が判明した。実例: 成長株モード Top10 の BUYシグナル6銘柄中5銘柄が SEPA Stage4（下降）。

パイプラインの役割を **「売買シグナル発生器」から「発掘エンジン（母集団生成・ランキング）」へ再定義**する。最終判定は二刀流（飛躍分析 / 深層分析）に委ね、パイプラインは「次に二刀流にかけるべき候補」を質の高い順に並べる。

**設計憲法との整合**: このプロジェクトは実証文化（Rank IC 診断で ROE 撤廃等）。本 Phase 1 は「Stage4 を上位に出さない」という**設計上明らかに正しい改善**のみを扱い、実証を要する変更（直近YoY反映）は Phase 2 に分離する。

## スコープ

### Phase 1（本 spec の対象）
- **A**: 成長株モードのテクニカルスコアに SEPA ステージを組み込む（配点再設計、Stage4降格）
- **B-1**: シグナルの意味を「売買シグナル」→「分析優先度」に再定義（値は後方互換維持）
- **B-2**: 出力に「次にかけるべき分析（飛躍/深層）」動線ブロックを追加

### Phase 2（別 spec・スコープ外）
- **C**: 最新決算の直近四半期 YoY をファンダ指標に反映。「直近YoYが α を上げる」仮説を `diagnose_growth` の backtest で検証してから採否を決める実証プロジェクト

## 確定した設計判断

| # | 判断項目 | 決定 |
|---|---|---|
| Q1 | パイプラインの役割 | 発掘エンジンに再定義（母集団生成・ランキング、判定は二刀流に委ねる） |
| Q2 | SEPA の組み込み方 | テクニカルスコアに SEPA 項を組み込む（案2）。ハードフィルタ除外（案1）でも signal限定（案3）でもない |

## A. テクニカルスコアの配点再設計（成長株モード）

現行 `_tech_score_single`（`services/pipeline_service.py`）のテクニカルスコア 100点を以下に再配分する。**バリュー株モード（mode='value'）の配点は変更しない**（今回の欠陥は成長株モード固有のため）。

| 要素 | 現行(growth) | 改修後(growth) | 配点ルール |
|---|---|---|---|
| SEPA stage | 0 | **30** | Stage2=30 / Stage3=15 / Stage1=10 / Stage4=0 |
| MA200乖離 | 30 | 20 | SEPA とトレンド系で重複するため圧縮 |
| RSI | 20 | 15 | |
| MACD | 20 | 15 | |
| 出来高 | 15 | 10 | |
| 高値ブレイク | 15 | 10 | |
| **合計** | 100 | 100 | |

**効果**: Stage4 銘柄はテクニカル上限 70点（SEPA 0）に頭打ちし、ランキング上位から自然に消える。母集団からは除外しない（見落とし防止）。

**SEPA stage 判定の出どころ**: `sector_comparison`（`self_signals.sepa_stage`）が既に算出しているロジックを流用する。実装時に該当の判定関数（batch_service / screener / stock_cache 計算経路）を特定し、`_tech_score_single` 内から呼ぶ、または stock_cache の stage 列を join する。新規のステージ判定ロジックは書かない（既存と二重化させない）。

## B-1. シグナルの「発掘ランク」化

`calc_trade_signals`（`services/pipeline_service.py`）:
- `signal` カラムの値は **BUY / WATCH / AVOID を維持**（呼び出し側・既存 CSV との後方互換）
- **意味を「分析優先度」に再定義**し、表示ラベルを変更:
  - BUY → 「優先精査」（即、二刀流にかける候補）
  - WATCH → 「監視」
  - AVOID → 「除外」
- BUY（優先精査）条件に **SEPA Stage2 または Stage3 を必須化**（Stage4 は優先精査にしない）。既存条件（総合≥60・テクニカル≥tech_min・RSI範囲・株価>MA25）に AND で追加

## B-2. 二刀流への動線

`pipeline_report` 出力（`_build_prompt` 周辺の整形 / `pages/7_pipeline_report.py` の表示）の冒頭に「**→ 次にかけるべき分析**」ブロックを追加:
- 成長株モード: 優先精査 × Stage2 の銘柄を「**飛躍分析推奨**」としてリスト。各行に `飛躍分析 <code>` のコマンドを添える
- バリュー株モード: 同様に「**深層分析推奨**」（`深層分析 <code>`）

これによりパイプライン（発掘）→ 二刀流（判定）の動線が出力上で明示される。

## 影響範囲

- `services/pipeline_service.py`:
  - `_tech_score_single` — SEPA stage 取得 + 配点再設計（growth のみ）
  - `calc_trade_signals` — BUY条件に Stage2/3 必須を追加、表示ラベル定義
  - 出力整形（`_build_prompt` または別の整形箇所）— 二刀流動線ブロック
- `pages/7_pipeline_report.py` — シグナル表示ラベル（「分析優先度」）、動線ブロックの描画
- SEPA stage 判定: 既存ロジック流用（新規ファイルなし）

## スコープ外（YAGNI）

- Phase 2 の C（直近YoY反映）はやらない（別 spec、diagnose 検証必須）
- バリュー株モードのテクニカル配点は変更しない（欠陥は成長株モード固有）
- 配点値（SEPA 30 等）の最適化は Phase 2 以降で diagnose を使って微調整（Phase 1 は妥当な初期値で固定）
- シグナル値（BUY/WATCH/AVOID）のリネームはしない（後方互換維持、意味と表示のみ変更）

## 成功基準

- 成長株モードの Top10 から Stage4 銘柄が（ほぼ）消える
- テクニカルスコアの SEPA 項が growth モードで機能し、value モードは不変
- `signal` が「分析優先度」として表示され、BUY=優先精査は Stage2/3 限定になる
- pipeline_report 出力の冒頭に「次にかけるべき分析（飛躍/深層）」ブロックがある
- バリュー株モードの挙動・スコアが回帰しない（不変）

## 検証方法

- `diagnose_growth` で改修前後の Top10 を比較:
  - `.venv/Scripts/python.exe diagnose_growth.py --fwd 60 --top 10 --snapshots 1`（短時間動作確認）
  - 改修前後で Top10 構成を比較し、Stage4 銘柄が上位から消えること、α（universe_alpha）が悪化しないことを確認
- 単一スナップショットで成長株モードを実行し、Top10 の各銘柄の SEPA stage を目視確認（Stage4 が上位に無い）
- バリュー株モードを実行し、スコア・シグナルが改修前と一致すること（回帰なし）を確認
- cp932 非互換文字を出力に混ぜない（既存 diagnose の制約に準拠）
