# ブレイクアウト順張り ペーパートレード 設計書

作成: 2026-09-22（Codex での要件整理を Claude Code が引き継ぎ）

## 目的

日本株の個別株スイング（数日〜数週間）の自動売買を、まずペーパートレード（仮想資金）で作る。
うまくいけば実運用へ移る。発注部分は差し替え可能にしておくが、実発注は今回の範囲外。

## 決定事項（利用者と合意済み）

- ペーパートレードから始める。TradingView MCP は発注に使わない（非公式 MCP の注意書きで実売買への使用禁止）
- 戦略は TradingView 系のテクニカル中心・スイング・ブレイクアウト順張り
- 対象は東証プライムかつ時価総額・売買代金の下限あり
- 仮想資金 300 万円、1 銘柄の最大損失は資金の 0.5%（1.5 万円）
- 構成は案A: シグナル判定は J-Quants の日足（`data/prices.parquet`）、TradingView は確認と描き込み・アラート

## 1. 売買ルール（初期値）

### 対象銘柄
- 時価総額 500 億円以上（`data/valuation.parquet` の `MktCap`、単位は百万円なので 50,000 以上）
- 20 日平均売買代金 5 億円以上（`prices.parquet` の `Va`）
- ETF・REIT を除く（決算短信のある銘柄 = `fins_cache` に登場する銘柄に限定）
- ペーパー運用ではさらに現在の市場区分がプライム（`stock_cache.market`）。
  バックテストは上場廃止銘柄の当時の市場区分が分からないため、区分条件は掛けない
  （現在の上場銘柄で試すと流動性条件を満たす 835 銘柄中 734 銘柄がプライム）

### 買い（D 日の大引けで判定、D+1 日の寄付きで約定）
1. 終値 > 50 日移動平均、50 日線 > 200 日線、200 日線 > 20 営業日前の 200 日線
2. 終値 > 前日までの 55 営業日の高値の最大値
3. 出来高 ≥ 50 日平均出来高 × 1.5
4. TOPIX 連動 ETF（1306）の終値 > その 200 日線
5. 次の決算発表予定日まで 3 営業日以上ある（`data/earnings_dates.parquet`。予定が無い銘柄は条件なしで通す）
6. 既に保有中・注文中の銘柄は除く

### 株数
- ATR は 20 日の Wilder 方式ではなく単純平均の真の値幅（True Range）
- 損切り幅 = ATR × 2（判定日の ATR）
- 株数 = floor(15,000 ÷ 損切り幅 ÷ 100) × 100
- 1 銘柄の金額上限は資金（その時点の時価評価額）の 20%。上限で株数を削り、100 株未満になれば見送り
- 現金不足時は出来高倍率の高い順に、買える分だけ
- リスク額は初期資金ではなく**その時点の資産の 0.5%**とする（資産が増えれば株数も増える）。
  初期は 300 万円 × 0.5% = 1.5 万円

### 売り
- 初期損切り = 約定値 − ATR × 2
- トレーリング = 保有開始後の最高値（高値）− ATR × 3（ATR は日々更新）。損切りラインは上げるのみ
- 判定: D 日の安値 ≤ 損切りライン → 約定値は min(D 日の始値, 損切りライン)（窓を開けた下落は始値）
- 損切りラインの引き上げは D 日の引け後に行い、D+1 日から有効
- 利益目標による売りは置かない

### 費用
- 手数料 0 円、スリッページ片道 0.1%（買いは約定値 × 1.001、売りは × 0.999）

### 株価のスケール
- すべて `services/split_adjust` で末尾日スケールに正規化した OHLCV を使う。
  ペーパー運用で保有中に分割があった場合は、保有株数・約定値・損切りラインを分割比で換算する

## 2. 検証の合格基準

### 第 1 段階: バックテスト（2022-02〜2026-09）
- 前半 2022-02〜2024-12 だけを見てルールを確定。後半 2025-01〜2026-09 は確定後に一度だけ確認し、見てからは直さない
- 合格条件（前半・後半とも）:
  1. 年率リターン > TOPIX（1306）の買い持ち
  2. プロフィットファクター ≥ 1.3
  3. 最大ドローダウン ≤ 20%
  4. 取引数 ≥ 50
  5. 周辺の値（高値期間 40/80 日、損切り ATR 倍率 2/3/4 の組み合わせ）でもプロフィットファクター ≥ 1.1
- 1 つでも満たさなければペーパー運用に進まず、原因を報告して相談

### 第 2 段階: ペーパー運用（最低 3 か月かつ 20 取引）
- 成績がバックテストの幅に収まる、想定約定値と実際の寄付き値のずれが小さいことを確認

### 第 3 段階: 実運用（範囲外）
- `paper_broker` を証券会社公式 API（候補: kabuステーション API）版に差し替え、資金の 1/3 程度から

## 3. 構成

| ファイル | 役割 |
|---|---|
| `services/breakout_strategy.py` | 指標（MA・ATR・55 日高値・出来高倍率）と判定。副作用なしの関数のみ |
| `services/paper_broker.py` | ペーパー口座（現金・保有・注文・約定）。`data/paper/` に保存。発注の窓口を固定し実運用で差し替える |
| `services/breakout_engine.py` | 1 営業日の処理。バックテストとペーパー運用の共通処理 |
| `scripts/breakout_backtest.py` | バックテスト・期間分割・周辺値確認。結果は `data/breakout_backtest/` |
| `pages/10_paper_trading.py` | 保有・資産推移（TOPIX 比較）・取引履歴・翌日の注文予定・手動実行ボタン |

### 1 営業日（D 日）の処理
1. 前日に作った買い注文を D 日の始値で約定（始値が無い = 売買停止なら注文を取り消す）
2. 保有銘柄の損切り判定（D 日の安値）
3. トレーリングの損切りラインを引き上げ
4. D 日の引けで買いを判定し、D+1 日の注文を作る
- 処理済みの最終日を記録し二重処理を防ぐ。抜けた日は古い順に処理して追いつく

### 運用の流れ
- Streamlit の「データ更新」の後に 1 営業日の処理を自動で実行（J-Quants API は Streamlit 側からのみ取得できるため）
- TradingView への反映は Claude Code に依頼（非公式 MCP で買値・損切りラインの線とアラート）。
  処理が `data/paper/tv_sync.json` に描く内容を書き出す。反映は任意で、記録の正しさには影響しない

### エラーの扱い
- 株価が欠けた銘柄は判定しない
- データが 3 営業日以上古い、または 1306 のデータが無い日は新規の買いを止め、画面に警告

### テスト
- 株数計算、損切り（窓を開けた下落を含む）、トレーリングが下がらないこと、二重処理しないこと、
  分割時の換算を小さな作り物のデータで確認

## 範囲外
実発注、日中の監視、空売り、複数戦略
