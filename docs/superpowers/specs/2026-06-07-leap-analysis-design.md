## 背景と目的

深層分析（`deep-analysis-jp`）は実弾の負け履歴（CANBAS ▲68% / サンバイオ ▲59% / QPS 高値掴み = 全て夢・テーマ・モメンタム側）から逆算した **FOMO 矯正具 = 拒否フィルター**。2026-06-06 の哲学レンズ追加で守備力は十分上がった。

しかし副作用として **深層分析を通過する銘柄がほぼ出てこず、投資が前に進まない**。守備を固めた結果、攻め手が消えた。これがユーザの実ペイン。

**目的**: 深層分析が門前払いするグロース・テーマ株の中から、「本物（化ける条件を満たす）」と「夢トラップ」を選別して救い上げる、**規律ある攻めの分析手法**を新設する。狙いは「規律あるグロース（中リスク・年+30〜50%級）」。テンバガー狙いの分散張りではない（それはユーザの負けパターンそのもの）。

**設計憲法**: 「規律あるグロース、もう大怪我はしない」。攻めの分析は、ユーザが過去に火傷した領域（実体ゼロのストーリー株を高値で掴む）に、今度はちゃんとした装備で再参入する道具。放置すれば夢トラップ製造機になる危険を常に意識し、ガードレールを内蔵する。

## ネーミング

**飛躍分析（Leap Analysis）/ スキル名 `leap-analysis-jp`**

- 深層（Deep・下に掘る・守備）↔ 飛躍（Leap・上に跳ぶ・攻め）の対比。意味・響き・英語の韻（deep/leap）すべてが対称。
- 「規律あるグロースで飛躍を狙う」という設計憲法とも一致。

## 飛躍分析の構造

### 設計憲法（深層分析と対をなす）

| | 深層分析 | 飛躍分析 |
|---|---|---|
| 役割 | 拒否フィルター（なぜ失敗するか） | 証拠フィルター（なぜ飛躍するか、ただし実証を要求） |
| 機能 | FOMO ブレーキ | 投資を前に進めるアクセル、ただしブレーキ内蔵 |
| 土俵 | バリュー+カタリスト | グロース・テーマ株（深層分析が門前払いする層） |
| 中核 | バフェット/マンガー流（拒否） | 成長エンジン実証 + タイミング + 価格規律（採用） |

### 深層分析との関係（最重要の線引き）

飛躍分析は**独立スキルとして並立**する。深層分析のフルの守備ゲート（安全マージン・割安要求）は**課さない** — 課したら通らないので、それがペインそのもの。

ただし「もう大怪我しない」憲法の最低防御線として、**致命傷ガードレールだけは内蔵**する。買い候補になったら任意で深層分析にもかけて守備視点をクロスチェックできる（二刀流）が、飛躍分析単独で判断は完結する。

### 中核構造（3層 + ガードレール）

- **中核 C：成長エンジンの実証** — KPI・売上の質・セグメント・単位経済が実際に回っている数字。**これが無ければ門前払い**（CANBAS・サンバイオ型をここで全部弾く）。飛躍分析の心臓部
- **タイミング A：SEPA ステージ** — Stage 2 初期 or 押し目を要求。**高値追いを禁止**（QPS 型をここで弾く）
- **価格 B：PEG / 成長対比バリュエーション** — 成長率に対して払い過ぎていないか
- **ガードレール：致命傷 4 種** — 夢トラップ / モメンタムトラップ / GC リスク（倒産）/ 増資希薄化。1 つでも該当 → 見送り or 基準厳格化

### レポート構造（深層分析が「失敗の解剖」なら、飛躍分析は「飛躍の設計図」）

1. **成長ストーリーの骨格** — 何を売って、なぜ伸びているか / TAM と現在地
2. **成長エンジンの実証**（中核 C）— KPI・セグメント・単位経済が回っている数字 ← 心臓部
3. **飛躍シナリオ** — 強気・基本の 2〜3 シナリオで到達 price target・倍率を定量化
4. **タイミングと価格**（A+B）— 今は押し目か高値追いか / PEG で払い過ぎていないか
5. **致命傷ガードレール** — 4 チェック。1 つでも該当 → 見送り or 基準厳格化
6. **総合判断** — 張る / 待つ / 見送り + サイジングの目安 + 監視する KPI トリガー

各セクションは深層分析の禁則を継承する（逃げ言葉禁止 / 装飾絵文字禁止 / 分割未調整 EPS 禁止 / 結論明言）。

## 実装形態とデータ供給

### 実装形態

Claude Code スキル `leap-analysis-jp`。深層分析と**完全に同じ骨格**（投資哲学 → 一次情報取得 → フレーム適用 → artifact → ダッシュボード HTML → wiki ingest → 要約）。学習コストゼロ、メンテも一系統に揃う。

### データ供給（既存資産フル活用、新規実装は最小）

| 用途 | データソース |
|---|---|
| 株価・テクニカル・SEPA ステージ・セクター percentile | `scripts/deep_analysis_helper.py`（既存、そのまま流用） |
| 成長エンジン実証（中核 C）= KPI トラックレコード・KPI コミットメント・セグメント・受注残 | EDINET DB MCP 直叩き（`get_kg_kpi_track_record` / `search_kg_kpi_commitments` / `get_segments` / `get_order_backlog`） |
| 最新 KPI 速報・成長ニュース・PTS | WebFetch |

→ **helper 改修なしで MVP 着手可能**。成長加速メトリクス（売上 YoY/QoQ の加速度・セグメント別成長）の helper 統合は Phase 2。

### 成果物と「二刀流の集約」

- artifact（日本語 Markdown）+ 財務ダッシュボード HTML（深層分析テンプレ流用、ただし**成長 KPI チャート中心**に差し替え）→ `<vault>/raw/conversations/{銘柄}-飛躍分析-{YYYY-MM-DD}/artifacts/`
- wiki ingest フローは深層分析と同一（source / entity / concepts / MOC / index / hot / log / manifest）
- **entity ページは深層分析と共有** — 同じ銘柄なら 1 ページに「深層分析の守備判定」と「飛躍分析の攻め判定」が両方載る。二刀流が 1 か所に集約される
- 新規 concept ページ（`wiki/concepts/`、既存スキーマ準拠）:
  - `[[成長エンジン実証]]` — ストーリーではなく KPI・単位経済が回っている証拠を要求する中核レンズ
  - `[[飛躍シナリオ]]` — 強気/基本シナリオで到達 price target・倍率を定量化する手法
  - `[[PEG（成長対比バリュエーション）]]` — 成長率に対する価格規律
  - `[[致命傷ガードレール]]` — 夢/モメンタム/GC/希薄化の 4 チェック
  - SEPA / レラティブストレングス / 夢トラップ / モメンタムトラップ は既存流用

### 発掘（候補供給）との接続

飛躍分析は 1 銘柄の深掘り。手前の候補発掘は別トラックで `diagnose_growth` / パイプラインレポートの**棚卸し**（実際に機能しているかの調査）をやってから繋ぐ。スキル自体は候補を 1 つ与えられれば動くため、発掘の整備は飛躍分析 v1 の前提条件ではない。
